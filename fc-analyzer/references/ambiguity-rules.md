# 区域歧义处理规则 — 灯具（Lighting）域专用

> 本文件用于处理用户输入存在歧义的情况，当一个关键词可能对应多个区域时，询问用户确认具体位置。
> 与 `viim-field-mapping.md`、`synonyms.md`、`semantic-rules.md` 配合使用。

## 歧义场景定义

### 场景 1：灯（通用词）

**用户输入：** "灯"、"那个灯"、"灯有问题"

**可能区域：**
- `EXT-Front End`（前灯/前雾灯/日行灯）
- `EXT-Rear End`（尾灯/后雾灯/刹车灯/牌照灯）
- `EXT-Side&Roof&Door`（侧转向灯/翼子板灯）
- `INT-Roof&Pillar`（阅读灯/车顶灯）
- `INT-IP&SW`（仪表灯/背光）
- `INT-Door Trim`（氛围灯/门板灯）
- `INT-Console`（中控灯/杯托灯）
- `INT-Luggage Compartment`（行李厢灯）

**处理方式：** 询问用户具体位置

**询问示例：**
```
请问是哪个灯有问题？
1. 前灯（前大灯/雾灯/日行灯）
2. 尾灯（尾灯/刹车灯/牌照灯）
3. 侧转向灯
4. 内饰灯（阅读灯/氛围灯/仪表灯等）
```

## 处理流程

### 1. 识别用户输入
从用户输入中提取关键词，检查是否在歧义场景列表中。

### 2. 检查是否存在歧义
如果关键词匹配到多个区域，则存在歧义，需要询问用户。

### 3. 询问用户
使用 `AskUserQuestion` 工具询问用户具体位置。

**询问格式：**
```
<关键词>可能在以下位置，请问具体是哪个？
1. <区域1描述>
2. <区域2描述>
3. <区域3描述>
...
```

### 4. 根据用户回答确定最终区域
根据用户选择的选项，确定最终的 VIIM 区域值。

### 5. 继续后续流程
使用确定的区域值继续后续的字段填充和推理。

## 处理规则

### 规则 1：优先匹配标准术语
如果用户输入直接匹配到标准术语（如"前灯"、"尾灯"），则直接使用对应的区域值，不需要询问。

### 规则 2：歧义场景优先
如果用户输入匹配到歧义场景，则优先使用歧义处理规则，询问用户确认。

### 规则 3：默认区域
如果用户输入无法匹配到任何区域，且不存在歧义：
- 判定为外饰灯具 → 默认 `EXT-Front End`
- 判定为内饰灯具 → 默认 `INT-Door Trim`

### 规则 4：用户回答格式
用户回答可以是：
- 数字选项（如"1"、"2"、"3"）
- 文字描述（如"前灯"、"尾灯"、"内饰灯"）

### 规则 5：多区域问题
如果用户输入涉及多个区域（如"前灯和尾灯都有问题"），则需要分别询问每个区域的具体问题。

### 规则 6：上下文消歧
如果上下文已明确位置，无需再次询问：
- 用户之前说过"前灯"，后续说"灯罩发黄" → 直接关联前灯
- 用户在讨论尾灯密封问题，后续说"进水了" → 直接关联尾灯

### 规则 7：组合描述消歧
当用户同时描述位置和组件时，优先使用组合信息：
- "前灯透镜" → 直接判定 `EXT-Front End`，无需询问
- "尾灯密封胶" → 直接判定 `EXT-Rear End`，无需询问

### 规则 8：泛指灯具类型消歧
当用户使用泛指但有方向性时：
- "前面的灯" → `EXT-Front End`
- "后面的灯" → `EXT-Rear End`
- "左边的灯" → 结合上下文判断前/后
- "右边的灯" → 结合上下文判断前/后

## 灯具域特殊歧义场景

### 特殊场景 1：同一个总成内的子功能
前灯总成内可能包含：近光灯、远光灯、日行灯、转向灯、雾灯。
当用户说"前灯"但问题只影响某个子功能时：
- 如果用户明确说"近光灯" → 直接关联前灯
- 如果用户只说"灯不亮" → 需询问"前灯的哪个功能不亮？近光/远光/日行灯/转向灯？"

### 特殊场景 2：左右对称件
前灯/尾灯通常是左右对称件。当用户未说明左右时：
- 如果问题描述中没有左右区分 → 默认为通用问题（左右都可能存在）
- 如果用户说"左边那个灯" → 记录但不区分（FC单通常不区分左右，描述中注明即可）

## 使用说明

1. **匹配优先级**：先检查是否匹配标准术语，再检查是否匹配歧义场景
2. **询问时机**：只有在存在歧义时才询问用户，避免不必要的询问
3. **询问措辞**：询问时要清晰列出所有可能的选项，方便用户选择
4. **用户回答**：支持数字选项和文字描述两种回答方式
5. **上下文消歧**：注意利用上下文信息减少不必要的询问
