# 语义理解规则 — 灯具（Lighting）域专用

> 本文件用于指导 AI 进行语义理解，提升灯具域自然语言识别的准确率。
> 与 `viim-field-mapping.md`、`synonyms.md`、`ambiguity-rules.md` 配合使用。

## 语义理解原则

### 1. 上下文理解

根据整个句子的语义判断关键词的含义，而不是孤立地匹配关键词。

**灯具域示例：**
- 用户说："前面那个灯亮度不够" → 理解为"前灯亮度衰减"
- 用户说："后面灯里面有水" → 理解为"尾灯进水"
- 用户说："灯罩发黄了" → 需结合上下文判断是前灯还是尾灯

### 2. 同义词替换

将用户输入替换为标准术语，便于后续匹配和处理。

**灯具域示例：**
- 用户说："大灯" → 替换为"前灯"
- 用户说："后灯" → 替换为"尾灯"
- 用户说："头灯" → 替换为"前灯"

### 3. 隐含信息推断

从用户输入中推断隐含信息，补充缺失的上下文。

**灯具域示例：**
- 用户说："灯罩发黄" → 推断可能是"UV老化"或"高温老化"
- 用户说："灯里面有雾" → 推断可能是"密封不良"或"透气阀堵塞"
- 用户说："灯不亮了" → 推断可能是"LED失效"或"驱动故障"或"线束接触不良"

## 语义理解规则

### 规则 1：灯具位置描述理解

**用户输入模式：** "前面的灯"、"后面的灯"、"上面的灯"、"侧面的灯"

**处理方式：**
- "前面的灯" / "车头灯" → 前灯（`EXT-Front End`）
- "后面的灯" / "车尾灯" → 尾灯（`EXT-Rear End`）
- "侧面的灯" → 侧转向灯（`EXT-Side&Roof&Door`）
- "车里面的灯" / "车内灯" → 内饰灯（需二次确认具体位置）
- "门上的灯" → 门板氛围灯（`INT-Door Trim`）
- "车顶的灯" → 阅读灯（`INT-Roof&Pillar`）

### 规则 2：灯具组件描述理解

**用户输入模式：** "灯里面那个"、"灯上面那个"、"灯后面那个"

**处理方式：**
- "灯里面那个" / "灯里面的东西" → 可能是LED模组/反射器/导光板，需询问
- "灯罩" / "灯壳" / "灯面" → 结构件
- "灯后面那个盖" → 后盖/密封盖
- "灯里面亮的那个" → LED模组/光源

### 规则 3：问题描述理解

**用户输入模式：** "灯有问题"、"灯不好用"、"灯坏了"

**处理方式：**
- "灯有问题" → 需询问具体问题（不亮？进水？起雾？开裂？）
- "灯不好用" → 可能是亮度不足/闪烁/调节失效
- "灯坏了" → 可能是不亮/开裂/脱落

### 规则 4：触发条件理解

**用户输入模式：** "XXX的时候"、"XXX时"、"XXX条件下"

**灯具域特定触发条件：**
- "开灯的时候" → 点亮后出现
- "关灯的时候" → 熄灭后出现
- "下雨的时候" → 淋雨条件下
- "洗车后" → 洗车后出现
- "冷车的时候" → 低温条件下
- "热了以后" → 高温条件下
- "走烂路的时候" → 振动条件下
- "时间长了" → 长时间使用后

### 规则 5：量化指标理解

**用户输入模式：** "超过XXX"、"大于XXX"、"低于XXX"、"不足XXX"

**灯具域特定量化指标：**
- "亮度衰减超过20%" → 光衰量化：>20%
- "色温偏了200K" → 色温偏移：200K
- "照射距离不够" → 功能性量化
- "亮了不到1000小时就坏了" → 寿命量化：<1000h
- "IP等级不够" → 防水等级量化
- "配光偏了2度" → 配光精度量化

## 语义理解示例

### 示例 1：位置 + 症状

**用户输入：** "大灯透镜在高温下亮度衰减"

**语义理解：**
1. 位置："大灯" → 前灯（`EXT-Front End`）
2. 组件："透镜" → 前灯透镜组件
3. 条件："高温下" → 高温环境
4. 症状："亮度衰减" → 光衰
5. 量化：未提及

**最终理解：** 前灯透镜高温光衰

### 示例 2：隐含信息推断

**用户输入：** "尾灯里面有水珠"

**语义理解：**
1. 位置："尾灯" → 尾灯（`EXT-Rear End`）
2. 症状："有水珠" → 进水
3. 隐含推断：密封失效（密封胶/密封条/透气阀问题）
4. 条件：未提及（可能是洗车后/淋雨后/涉水后）

**最终理解：** 尾灯密封失效导致进水

### 示例 3：模糊描述

**用户输入：** "灯不亮了"

**语义理解：**
1. 位置："灯" → 歧义（前灯？尾灯？内饰灯？）→ 需询问
2. 症状："不亮" → 完全失效
3. 隐含推断：可能是LED失效/驱动故障/线束断路/保险丝烧毁

**处理：** 询问"请问是哪个灯不亮？前灯/尾灯/内饰灯？"

### 示例 4：条件 + 症状

**用户输入：** "洗车后灯里面有雾气"

**语义理解：**
1. 条件："洗车后" → 高压水冲洗后
2. 症状："有雾气" → 起雾
3. 隐含推断：密封不良（密封胶/透气阀问题），高压水渗入
4. 位置："灯" → 歧义，需询问

**处理：** 询问"请问是哪个灯起雾？前灯/尾灯？"

### 示例 5：组件 + 量化

**用户输入：** "前灯LED模组亮了500小时就衰减了30%"

**语义理解：**
1. 位置："前灯" → 前灯（`EXT-Front End`）
2. 组件："LED模组" → 前灯LED光源组件
3. 症状："衰减" → 光衰
4. 量化1："500小时" → 寿命：<500h（异常偏低）
5. 量化2："30%" → 衰减幅度：30%
6. 严重度：A（>30%）

**最终理解：** 前灯LED模组500h光衰30%，严重度A

## 灯具域特殊语义模式

### 模式 1：光学路径描述

用户可能从光路角度描述问题：
- "出光不均匀" → 配光/导光板问题
- "光斑有暗区" → 亮度不均
- "截止线不清楚" → 配光精度
- "光打不远" → 照射距离不足
- "光照到天上去了" → 灯光高度偏高
- "光照到地上了" → 灯光高度偏低

### 模式 2：材料老化描述

用户可能从材料角度描述：
- "灯壳脆了" → 材料老化/发脆
- "灯罩雾了" → 透明件雾化
- "灯壳发黄了" → UV老化/热老化
- "密封胶硬了" → 密封胶老化
- "反光层掉了" → 反射器镀层脱落

### 模式 3：电气描述

用户可能从电气角度描述：
- "灯闪" → 频闪/闪烁
- "灯抖" → 光强波动
- "灯自己亮" → 异常自动点亮
- "灯关不掉" → 常亮故障
- "灯一半亮一半不亮" → 部分LED失效

## 语义理解流程

```
用户输入
  ↓
① 位置描述理解（哪个灯？前灯/尾灯/内饰灯？）
  ↓
② 组件描述理解（灯的哪个部分？透镜/灯壳/LED？）
  ↓
③ 症状描述理解（什么问题？不亮/进水/光衰？）
  ↓
④ 条件描述理解（什么条件下？高温/振动/洗车？）
  ↓
⑤ 量化指标理解（多严重？衰减多少？偏移多少？）
  ↓
⑥ 综合理解结果
  ↓
⑦ 检查是否需要歧义澄清（参见 ambiguity-rules.md）
  ↓
⑧ 继续后续流程
```

---

## 使用说明

1. **优先级**：先位置，再组件，再症状，再条件，最后量化
2. **上下文**：根据整个句子语义理解，不孤立匹配关键词
3. **推断**：对未提及信息进行合理推断，但需标注"推断"
4. **确认**：无法确定时询问用户
5. **灯具域特殊性**：注意光学/密封/电气三类特殊语义模式
